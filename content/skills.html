02 / Learning & proof

Learn to deliver, not just follow.

Choose your primary route after the 14-day comparison. Then learn the minimum coherent skill set needed to produce credible work samples and qualify for reachable roles.

Three learning sequences—not three simultaneous projects

A / BUILD

Programming → data → a small app → dependable delivery

Work through one language, SQL, version control, a simple interface, tests and deployment. Use the detailed sample syllabus below. Advance by demonstrated ability, not because a week has ended.

Ready for the next stage: a reviewer gives you a small changed requirement and you can implement, explain and test it with normal tools.

B / INVESTIGATE

Product knowledge → testing → SQL/API basics → clear support

Learn browser developer tools, HTTP, test cases, reproducible bug reports, data queries, account permissions and escalation. Practise a 10-minute English customer explanation. Add test automation after you understand the tests.

Proof pack: five accurate bug reports on an authorized app, a test plan, a troubleshooting decision tree and a short user guide. Find and fix errors in your own explanation.

C / STABILIZE

Existing competence → a paid task → a sustainable learning block

Test one reachable service: legitimate office/spreadsheet operations, technical support, product demonstrations, or tutoring a subject you can teach accurately. Study the role’s actual work; do not buy a generic freelancing course.

Proof pack: a representative sample, feedback from someone who performs that work, and an application or offer with clear pay and hours. Sales skill is not established by confidence alone.

Time to proficiency is uncertain. These routes are not guaranteed to be equally accessible or equally paid. Work samples should reveal what to practise next.

The development syllabus below is one option: Python/SQL/Django is convenient for teaching data and backend concepts. It is not a market-validated winner for Dhaka. Use the language and framework that match your strongest existing skill, a good supervisor and reachable roles; PHP, JavaScript, Java or .NET may be more appropriate. Choose one stack rather than learning them all.

Development route: a two-hour baseline

From a blank folder, read a small CSV of orders, reject invalid amounts, calculate totals by customer, and save a summary. You may use documentation. Spend the first 30 minutes without a tutorial or AI-generated solution. Then record what blocked you: syntax, breaking down the task, files, data structures, or debugging.

If you cannot finish, that is a starting measurement, not a verdict on your ability. Rebuild it at the end of week two with different fields and requirements. The improvement matters more than the first score.

A method to escape tutorial dependence

Calendar correction: the week ranges above are possible study windows, not validated learning-speed estimates. Repeat a stage if you cannot pass its proof task; reduce scope or choose more supervision before accepting production responsibility.

1

Learn a small piece.

Watch or read for 20–40 minutes. Write a short explanation of the concept in your own words. Avoid copying a whole application and calling it mastery.

2

Close it and reconstruct.

Rebuild the feature from a blank file. Documentation is allowed. When stuck, ask for a hint or an explanation of an error before requesting a complete solution.

3

Change the problem.

Add partial payments, missing records, duplicate IDs or a second user role. Transfer to a new requirement is stronger evidence than reproducing familiar steps.

4

Test, explain, and repeat later.

Write edge cases. Explain the data flow without reading the code. Rebuild a related task a few days later. Maintain a short “mistakes I can now fix” log.

If you choose development: three portfolio artifacts

01 · Small and complete

Messy CSV → reliable report

Import files with inconsistent dates, duplicates and missing values. Produce a reconciliation report with rejected rows and clear totals.

Evidence: sample inputs, tests, README, a two-minute demonstration, and a fresh requirement completed without a tutorial.

02 · Useful application

Orders → payments → follow-up

Track orders, amounts owed and payment status. Include separate user roles, search, exports, audit history and a documented backup restore.

Evidence: a deployed synthetic-data demo, feedback from three users, fixed bugs and an explanation of tradeoffs.

03 · Reliability case study

A broken workflow → a measured fix

Simulate an API failure or inconsistent import. Add validation, retries where safe, logging and a human review step.

Evidence: before/after error rates on a stated test set. Label simulated results; do not invent business savings or customers.

The equally important noncoding stack

  • English and clear Bangla: write a concise update, ask clarifying questions, explain a delay and conduct a 15-minute discovery conversation. Record a short English demo weekly.
  • Commercial understanding: learn revenue, gross margin, contribution margin, inventory, receivables, cash flow and customer acquisition. Ask what an error costs and who approves a purchase.
  • Professional reliability: use version control, make realistic commitments, flag problems early and write handover notes. Being pleasant and dependable helps a team trust your technical work.
  • Learning judgment: distinguish not knowing a tool from not understanding a concept. Learn a new tool when a project requires it; continue strengthening data structures, algorithms, databases, networks and operating systems through your degree.

Use AI as a tool you can supervise

For learning, ask it to quiz you, explain an error, compare designs or suggest tests. For production, define acceptance criteria, keep changes small, inspect the diff and run checks. Never submit customer secrets or confidential records to an unapproved service. Follow course rules about permitted assistance.

Once a week, solve one small task without generated code to verify that your own skill is growing. On a second task, use AI and track time to a correct result, including review and rework. You are learning how to use assistance without losing the ability to reason.

Do not add yet: Kubernetes, several frontend frameworks, deep-learning specialization, multiple certifications, expensive bootcamps or a new computer. A working laptop is usually sufficient for the introductory tasks. Buy a tool only when a specific paid or learning task justifies the cost.

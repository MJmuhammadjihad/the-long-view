# Launch kit

These are editable drafts and a manual distribution plan. They have not been posted or sent. Adapt the wording to what is actually shipped and verify every link before publishing.

## Positioning

**Name:** The Long View

**One line:** An open career and money decision toolkit: compare earning routes, price a degree, test your cash runway, and record what changes your mind.

**Short description:** A standalone HTML guide with five calculators, an evidence-based reading path, and local notes. General decision principles sit alongside dated Bangladesh examples. It is designed to make assumptions visible, not predict who will get rich.

**Repository:** https://github.com/MJmuhammadjihad/the-long-view

**Demo:** https://mjmuhammadjihad.github.io/the-long-view/

**Primary visual:** `assets/cover.svg`. A diagram or illustration should not be described as a screenshot. Use actual rendered screenshots or recordings when demonstrating the interface.

## Before announcing

- Confirm the public demo, HTML download, source links, and latest release work.
- Verify that the repository and screenshots contain no private profile or journal data.
- Check the license, contribution instructions, and reporting routes.
- Read the README as a first-time visitor; make the first useful action obvious.
- Record a short, honest demonstration using synthetic inputs.

## A useful 45-second demonstration

1. Start with the question: “What happens if the job starts two months later?”
2. Enter clearly labelled illustrative spending and support numbers.
3. Show where the six-month cash plan first goes negative.
4. Open the route comparison and a decision-journal prompt.
5. End with the demo and repository links, inviting one concrete kind of feedback.

Do not hide a bad outcome or imply that one scenario predicts someone’s future. The useful result is understanding the tradeoff.

## A sustainable distribution plan

| Stage | Action | Useful signal |
| --- | --- | --- |
| First release | Publish a clear README, working demo, versioned HTML asset, and concise release notes. | A new visitor can understand and use the project without help. |
| First feedback | Share in one relevant student, developer, or personal-finance community where self-promotion is permitted. | Specific reports of usefulness, confusion, or failure. |
| Follow-up | Fix a real reported issue and explain the improvement with a small example. | Returning users or contributors can see that feedback matters. |
| Ongoing | Publish occasional substantive updates and sourced regional improvements. | Repeat usage, useful issues, and accepted contributions. |

A star is a lightweight signal of interest. Downloads, useful feedback, repeat usage, and contributions provide different information. None guarantees a sustainable audience. Do not invent usage figures, endorsements, benchmarks, testimonials, or comparisons.

Avoid bulk direct messages, unsolicited tagging, paid or exchanged stars, fake accounts, repetitive link posting, or manufactured urgency. Ask communities for permission when their rules require it. Contributors should be credited for actual work.

## Repository presentation checklist

- Short description and homepage URL match the shipped project.
- Topics describe real functionality, such as career-development, personal-finance, decision-making, financial-literacy, and offline-first.
- README opens with a clear problem and a direct path to trying the tool.
- Release notes describe actual behavior and known limits.
- Issue forms invite reproducible bugs and evidence corrections.
- A star invitation is optional and brief; the project remains useful without it.

There is no reliable way to guarantee stars. The controllable goal is to make a useful project easy to understand, try, trust, and improve.
